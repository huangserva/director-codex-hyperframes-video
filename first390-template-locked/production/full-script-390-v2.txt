80万人看过的 Codex 加 Remotion 实战，已经帮助很多小伙伴入门。今天我们继续往前走，用 Agent 制作像这样的高级感动画视频。

这一次重点测试 HyperFrames。你现在就可以用 Codex、Claude Code 这种 Agent，制作科技感口播视频。HyperFrames 到底是什么？怎么配合 Codex，用一句话渲染出视频？我用这期视频讲清楚。

简单说，HyperFrames 是一个开源框架，可以用写 HTML 网页的方式来构建视频。HTML、CSS、JavaScript 能实现的视觉效果，理论上都可以被它渲染出来。

这也是它适合 Agent 的原因。因为视频内容本质上是页面结构、样式、动画和时间轴，大模型不用理解复杂剪辑软件，也能一步一步把画面做出来。

下面我们用 Codex 创建第一个 HyperFrames 视频。先不做复杂效果，只测试它能不能一句话出片。直接输入提示词：请创建一个 Codex 安装教程，要求一九二零乘一零八零，包含科技感配色、字幕、动画和完整时间轴。

接着 Agent 开始创作。第一步，确认制作规范。它不是随便生成网页再录屏，而是先确认尺寸、时长、素材、字幕、动画和输出格式。

第二步，联网搜索。因为视频要讲 Codex 安装，Agent 会先读取官方文档，明确当前版本需要展示哪些步骤。

第三步，检查环境。HyperFrames 渲染视频需要 Node、FFmpeg、Chrome 这些依赖。如果本地没有装，Agent 会继续完善环境。

第四步，初始化项目。生成以后，你会看到完整的项目目录。不会编程也没关系，现在你只需要用自然语言描述目标。

第五步，建立视觉风格。Agent 会写下字体、颜色、背景、卡片、动效和字幕规则，让后面的画面统一在同一套系统里。

所以 HyperFrames 的价值，不只是生成视频，而是把视频制作变成可以复用、可以检查、可以反复修改的工程流程。对 Agent 来说，这比传统剪辑软件更容易理解，也更容易稳定复刻。

到这里，第一个版本已经跑通。内容、环境、工程、设计都准备好了，接着 Agent 开始编码，并启动 HyperFrames Studio 做预览。

几分钟以后，MP4 会输出到项目目录。你看，这就是 Codex 加 HyperFrames 的第一条视频。它能证明流程可行，但画面更像 PPT 演示，还不是我们想要的高级感口播模板。

如果要继续往上做，重点就不是多加几个动画，而是把拍摄、设计、脚本、分镜、配音、制作、验证这些步骤，全都变成 Agent 能理解的文件。

我们先看 HyperFrames 官方推荐的制作流程。它并不神秘，本质上也是先准备素材，再明确设计，再写脚本和分镜，最后渲染成视频。

区别在于，传统剪辑里很多判断都在剪辑师脑子里；Agent 工作流里，这些判断必须写下来，变成可读取、可复用、可检查的规则。

第一步，准备口播视频。它可以是真人口播，也可以是 DUIX 这种数字人模板。只要需要口型同步，后面就不能让每个小片段自己带声音，而要统一用一条完整主音轨。

第二步，准备设计资产。因为 HyperFrames 是用 HTML、CSS、JavaScript 做视频，所以我们可以像设计网页一样，先把整条视频的视觉系统做出来。

这里可以用 Claude 生成网页原型，也可以用 Open Design、Stitch 这类工具生成设计稿。关键不是工具，而是输入要清楚：深色科技背景、蜂窝纹理、金色标题、蓝色强调、玻璃面板、右侧人物视频栏。

如果有参考图，也要一起放进去。参考图的价值，是让 Agent 学会画面的层次：主标题在哪里，功能卡在哪里，人物视频多高，底部进度线怎么放。

设计稿出来后，不要马上渲染。先检查版式是不是对。概念解释场景，左侧信息栏要足够大，有小标签、英文 kicker、超大中文标题、短副标题、功能卡片和底部进度线。

右侧人物视频栏要和左侧保持同一套高度体系。视频必须居中、满框、带金色边框和轻微发光，不能顶部留黑边，也不能用静态图片冒充视频。

操作演示场景则不一样。它的主体应该是屏幕录制，前景层占最大面积。右下角可以放一个圆形移动 PIP，但这个 PIP 只是辅助讲解，不能抢走主体。

这就是我们现在要固定的 scene type 规则：概念讲解用左右分栏；屏幕操作用大屏录制加圆形 PIP；步骤过渡用深色步骤卡；结果展示用真实结果蒙太奇；总结收尾再回到人物或总结卡。

不能因为某一段出现圆形视频，就把所有人物都做成圆形。也不能因为某一段是教程，就把所有画面都塞进屏幕录制。先判断场景目的，再套对应组件。

第三步，把设计资产写成 Design.md。这个文件不是一句“做高级一点”，而是给 AI Agent 的设计说明书。

它要明确字体体系、字号层级、主色和辅助色、背景纹理、卡片圆角、边框发光、视频裁切、字幕位置、以及每种场景应该使用的固定版式。

有了 Design.md，Agent 才不会每一段都重新发挥。它会在同一个视觉系统里做扩展，避免后半段突然变成另一套风格。

第四步，准备脚本。口播视频的脚本不能只是一段普通文案，最好能拆成带时间轴的旁白。至少要知道每一段话服务于哪个场景。

这也是我们这次最重要的流程：声音先行。先生成完整 390 秒主音轨，再做字幕、口型和画面。

为什么不能反过来？因为如果先做画面，再把每段数字人视频的声音拼进去，就会出现有数字人的地方有声音，没有数字人的地方突然没声音。听起来就会断，字幕也会飘。

正确做法是，全片只有一条连续主音轨。DUIX 生成的人物视频全部静音，只负责嘴型和画面。最后合成时，把主音轨统一 mux 到成片里。

主音轨生成以后，再跑 ASR，得到字幕时间轴。字幕必须来自最终声音，而不是手写时间表。只要 TTS 速度变了，就重新 ASR，不能手动一点点挪。

DUIX 也是同一个逻辑。比如一百九十秒到一百九十八秒出现右侧人物，就从主音轨里切出这一段，转成四十四点一千赫兹单声道 WAV，再提交给 DUIX 做口型。

这样，字幕、声音、嘴型都来自同一个源头。后面无论画面怎么切，最终都不会出现声音连续性断掉、人物口型从别处截取、字幕和说话差几秒的问题。

第五步，生成 storyboard.md。它是给 HyperFrames 的分镜说明书，要写清楚每个镜头的时间、用途、组件、文字、素材槽、入场动效和离场动效。

比如开头的 87 万统计，不只是一个数字。左侧数据要进场放大，中间视频要突然 punch in，右侧框线要延伸出来，这些都要写成规则。

再比如左右分栏，不是随便一左一右。左侧必须是强文字信息栏，右侧是移动人物视频栏，两个区域的高度和视觉重量要统一。

屏幕演示则要保持一层背景、一层主体、一层必要 HUD。不要叠很多空框，也不要出现没有内容的圆圈。画面越复杂，越要守住主体。

等设计、脚本、时间轴都准备好以后，我们就可以让 Agent 生成 storyboard.md。这个文件会包含视频规格、设计摘要、分镜节奏、画面目标，以及每个镜头要呈现的内容。

你可以把它理解成 HyperFrames 的施工图。没有这张施工图，Agent 只能临场发挥；有了它，Agent 才能按同一套模板稳定复刻。

最后我们总结一下完整流程。第一，确定主题和脚本。第二，生成连续主音轨。第三，ASR 得到字幕。第四，从主音轨切 DUIX 驱动音频。第五，生成数字人口型视频。

第六，准备屏幕录制和设计资产。第七，把每个片段分类为统计开场、标题卡、概念分栏、屏幕演示、步骤卡、证明蒙太奇或总结收尾。第八，用 HyperFrames 渲染无声画面。

最后，把连续主音轨合成进去。这样声音不会断，字幕不会飘，数字人口型也不会因为场景切换而错位。

你在这期内容里看到的 HyperFrames 素材，基本都可以用这套流程制作。先准备设计资产，再准备带时间轴的口播脚本，然后生成 storyboard.md，最后让 Agent 根据分镜写 HyperFrames 代码并渲染成视频。

这套方法看起来步骤多，但它解决的是稳定性。一次跑通不难，难的是换主题、换数字人、换脚本以后，还能做出同样的版式、同样的节奏和同样的口播质感。

如果你自己尝试，建议先从二十秒模板开始。把声音、字幕、口型、画面全部对齐，再扩到两分钟，最后再做六分钟。不要一上来就追求全片，否则任何一个环节错了，后面都会一起错。
