80万人看过的 Codex 加 Remotion 实战，已经帮助很多小伙伴入门。今天我们继续往前走，用 Agent 制作像这样的高级感动画视频。

这一次重点测试 HyperFrames。你现在就可以用 Codex、Claude Code 这种 Agent，制作科技感口播视频。HyperFrames 到底是什么？怎么配合 Codex，用一句话渲染出视频？我用这期视频讲清楚。

简单说，HyperFrames 是一个开源框架，可以用写 HTML 网页的方式来构建视频。HTML、CSS、JavaScript 能实现的视觉效果，理论上都可以被它渲染出来。

这也是它适合 Agent 的原因。因为视频内容本质上是页面结构、样式、动画和时间轴，大模型不用理解复杂剪辑软件，也能一步一步把画面做出来。

下面我们用 Codex 创建第一个 HyperFrames 视频。先不做复杂效果，只测试它能不能一句话出片。直接输入提示词：请创建一个 Codex 安装教程，要求一九二零乘一零八零，包含科技感配色、字幕、动画和完整时间轴。

接着 Agent 开始创作。第一步，确认制作规范。它不是随便生成网页再录屏，而是先确认尺寸、时长、素材、字幕、动画和输出格式。

第二步，联网搜索。因为视频要讲 Codex 安装，Agent 会先读取官方文档，明确当前版本需要展示哪些步骤。

第三步，检查环境。HyperFrames 渲染视频需要 Node、FFmpeg、Chrome 这些依赖。如果本地没有装，Agent 会继续完善环境。

第四步，初始化项目。生成以后，你会看到完整的项目目录。不会编程也没关系，现在你只需要用自然语言描述目标。

第五步，建立视觉风格。Agent 会写下字体、颜色、背景、卡片、动效和字幕规则，让后面的画面统一在同一套系统里。

所以 HyperFrames 的价值，不只是生成视频，而是把视频制作变成可以复用、可以检查、可以反复修改的工程流程。对 Agent 来说，这比传统剪辑软件更容易理解，也更容易稳定复刻。

到这里，我们已经跑通了第一个版本。内容、环境、工程、设计都已经就位，接着 Agent 会开始编码并渲染视频。

经过几分钟处理，Agent 会启动 HyperFrames Studio 的预览界面，并把 MP4 视频输出到项目目录。你看，这就是 Codex 加 HyperFrames 的第一条视频。它已经能跑通完整流程，但现在更像一个 PPT 演示视频。

如果你想让口播视频更有高级感，关键就不是只让 Agent 写代码，而是要把拍摄、设计、脚本、分镜、配音、制作、验证这些步骤，全部变成它能理解的输入。

我们来到 HyperFrames 的官方文档。这里已经把推荐流程讲得很清楚：先准备素材，再明确设计，再写脚本和分镜，最后由 HyperFrames 渲染成视频。

你会发现，这跟我们平时做口播剪辑并没有本质区别。区别在于，以前这些信息都在剪辑师脑子里，现在要把它们变成文件，交给 Agent 执行。

第一件事，是准备好你的口播视频。这里的视频不一定要和最终画面完全一样，但它必须能提供真实的人物、表情、动作和节奏。只要有口型同步需求，后面就要用同一条主音轨切片去驱动数字人视频。

第二件事，是进入设计环境。前面说过，HyperFrames 是用 HTML、CSS 和 JavaScript 来构建视频，所以我们完全可以像设计网页一样，先把整条视频的视觉风格做出来。

如果你习惯用 Claude，可以直接让 Claude 做一套网页原型。也可以用 Open Design、Stitch 这一类工具，先输出页面结构、排版、颜色、字体、组件和动效方向。

这里最重要的不是工具名字，而是输入方式。你要告诉 Agent：这条视频是科技感口播，要有深色背景、蜂窝纹理、金色主标题、蓝色功能点、玻璃质感面板，以及右侧人物视频栏。

如果你有喜欢的参考图，也要一起放进去。参考图的作用不是让 Agent 随便抄一张图，而是让它学习画面的层次：哪里是主标题，哪里是信息卡，哪里是视频栏，哪里是进度线。

设计稿出来以后，不要急着渲染。先检查它是不是满足我们要的版式：左侧信息栏要足够大，标题要有层次，右侧人物视频要居中、要动、要满框，不能出现空的 HUD 圆圈，也不能随便叠一堆半透明框。

这一步决定了后面整条视频的质感。如果左边只是堆几个小图标，右边随便放一个裁切不对的视频，那就算动效再多，也不会像一个专业口播模板。

第三件事，是把设计资产放进 HyperFrames 项目。这里最重要的文件，就是 Design.md。你可以把它理解成给 AI Agent 看的设计说明书。

Design.md 不只是写几句“做得高级一点”。它应该明确字体体系、字号层级、主色和辅助色、卡片圆角、边框发光、背景纹理、视频裁切规则、字幕位置，以及每类场景应该用哪种版式。

比如，概念解释场景，就用左侧大信息栏加右侧人物视频栏。操作演示场景，就让屏幕录制成为主体，右下角只放一个圆形移动 PIP。步骤过渡场景，就用深色步骤卡，不要硬塞人物。

这个分类非常重要。不能因为原片后面出现了一个圆形视频，就把所有右侧人物栏都改成圆形；也不能因为某一段是教程，就把所有画面都做成屏幕录制。先判断场景目的，再选择组件。

第四件事，是准备脚本。对于这种口播视频来说，脚本最好不只是普通文案。它还应该带有清晰的时间轴，或者至少能被拆成连续的旁白段落。

为什么我们这次特别强调声音先行？因为画面、字幕、口型，最终都要跟声音对齐。如果先做视频，再临时把每段数字人音频塞进去，就会出现有数字人时有声音、没数字人时没声音的问题。

正确做法是先生成一条完整主音轨。全片从第一秒到最后一秒，旁白都在这条主音轨里连续存在。后面所有 DUIX 数字人视频，只负责画面和口型，全部静音。

有了主音轨以后，再用 ASR 识别出字幕时间轴。这样字幕是从最终声音里来的，不是从手写时间表里猜出来的。只要 TTS 速度变了，就必须重新跑 ASR，不能手动一点点挪字幕。

同样，DUIX 的口型视频也要从这条主音轨里切音频。比如某个画面从一百九十秒到一百九十八秒出现人物，那就从主音轨里切出这一段，转成四十四点一千赫兹单声道 WAV，再提交给 DUIX。

这样最后合成时，HyperFrames 里只有一条全局声音。人物视频即使在不同场景切换，嘴型也会跟同一条声音对齐，不会再出现某一段从别的位置截视频、口型和字幕完全错开的情况。

第五件事，是生成 storyboard.md。它不是普通分镜表，而是给 HyperFrames 和 Agent 的视频制作说明书。里面应该写清楚每个镜头的时间、用途、组件、文字、素材槽、动画进入方式和退出方式。

比如开头的 87 万统计，不只是一个数字。它有从左侧进入、数字放大、中央视频突然放大、右侧框线延伸出来的节奏。要复刻这种效果，就必须在 storyboard 里写清楚入场的顺序和力度。

再比如概念分栏画面。左边大信息栏和右边视频栏必须保持统一高度体系。左边不是随便放标题，而是有小标签、英文 kicker、超大中文标题、短副标题、功能卡片和底部进度线。

右侧人物栏也不能只是缩小视频。它要有金色边框和轻微发光，人物要居中，视频要填满框，不能顶部留黑边。如果这是视频槽，就必须播放动态视频，而不是用一张静态截图冒充。

操作演示画面则相反。主角应该是屏幕录制本身，前景层占最大面积，右下角圆形 PIP 只是辅助讲解。这里允许圆形人物，但不允许再叠一堆空框、红蓝框、半透明卡片，把主体画面弄乱。

所以我们现在做模板，不是只做一条视频，而是沉淀一套可复用的制作规则。以后只要换主题，先写脚本，生成主音轨，再从主音轨切 DUIX，最后按 scene_type 套组件，就能稳定复刻同一种质感。

最后我们回到这条视频的完整流程。第一步，明确主题和脚本。第二步，生成连续主音轨。第三步，用 ASR 得到字幕时间轴。第四步，从主音轨切出 DUIX 驱动音频。第五步，生成数字人口型视频。

第六步，整理设计资产和 screen recording。第七步，把每个片段分类为统计开场、标题卡、概念分栏、屏幕演示、步骤卡、证明蒙太奇或总结收尾。第八步，用 HyperFrames 渲染无声画面。

最后一步，把连续主音轨重新合成到成片里。这样声音不会断，字幕不会飘，数字人口型也不会因为场景切换而错位。

你在这期内容里看到的所有 HyperFrames 素材，基本都可以用这套方式做出来。先准备设计资产，再准备带时间轴的口播脚本，然后生成 storyboard.md，最后让 Agent 根据分镜写 HyperFrames 代码，并渲染成视频。

这套方法看起来步骤多，但它解决的是稳定性问题。一次能跑通不难，难的是下一次换主题、换数字人、换脚本，仍然能做出同样的版式、同样的节奏、同样的口播质感。

如果你想自己尝试，可以先从一个二十秒模板开始。把声音、字幕、口型、画面全部对齐，再扩展到两分钟，最后再做六分钟。不要一上来就追求全片，否则任何一个环节错了，后面都会一起错。
