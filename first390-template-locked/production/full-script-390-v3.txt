80万人看过的 Codex 加 Remotion 实战，已经帮助很多小伙伴入门。今天我们继续往前走，用 Agent 制作像这样的高级感动画视频。

这一次重点测试 HyperFrames。你现在就可以用 Codex、Claude Code 这种 Agent，制作科技感口播视频。HyperFrames 到底是什么？怎么配合 Codex，用一句话渲染出视频？我用这期视频讲清楚。

简单说，HyperFrames 是一个开源框架，可以用写 HTML 网页的方式来构建视频。HTML、CSS、JavaScript 能实现的视觉效果，理论上都可以被它渲染出来。

这也是它适合 Agent 的原因。因为视频内容本质上是页面结构、样式、动画和时间轴，大模型不用理解复杂剪辑软件，也能一步一步把画面做出来。

下面我们用 Codex 创建第一个 HyperFrames 视频。先不做复杂效果，只测试它能不能一句话出片。直接输入提示词：请创建一个 Codex 安装教程，要求一九二零乘一零八零，包含科技感配色、字幕、动画和完整时间轴。

接着 Agent 开始创作。第一步，确认制作规范。它不是随便生成网页再录屏，而是先确认尺寸、时长、素材、字幕、动画和输出格式。

第二步，联网搜索。因为视频要讲 Codex 安装，Agent 会先读取官方文档，明确当前版本需要展示哪些步骤。

第三步，检查环境。HyperFrames 渲染视频需要 Node、FFmpeg、Chrome 这些依赖。如果本地没有装，Agent 会继续完善环境。

第四步，初始化项目。生成以后，你会看到完整的项目目录。不会编程也没关系，现在你只需要用自然语言描述目标。

第五步，建立视觉风格。Agent 会写下字体、颜色、背景、卡片、动效和字幕规则，让后面的画面统一在同一套系统里。

所以 HyperFrames 的价值，不只是生成视频，而是把视频制作变成可以复用、可以检查、可以反复修改的工程流程。对 Agent 来说，这比传统剪辑软件更容易理解，也更容易稳定复刻。

到这里，第一个版本已经跑通。内容、环境、工程、设计都准备好了，接着 Agent 开始编码，并启动 HyperFrames Studio 做预览。

几分钟以后，MP4 会输出到项目目录。你看，这就是 Codex 加 HyperFrames 的第一条视频。它证明流程可行，但画面更像 PPT 演示，还不是高级感口播模板。

如果想继续往上做，重点不是多堆几个动效，而是把拍摄、设计、脚本、分镜、配音、制作、验证，全部变成 Agent 能读懂的文件。

我们先看 HyperFrames 的推荐流程。它和传统口播剪辑并不冲突：先准备素材，再明确设计，再写脚本和分镜，最后渲染成视频。

区别在于，以前很多判断都在剪辑师脑子里；现在要把这些判断写进项目，让 Agent 可以复用，也可以被我们检查。

第一步，准备口播视频。它可以是真人口播，也可以是 DUIX 数字人模板。只要有口型同步需求，就不能让每个视频片段各自带声音。

正确做法是先做一条连续主音轨。全片从第一秒到最后一秒，都以这条声音为准。DUIX 视频全部静音，只负责画面和嘴型。

第二步，准备设计资产。HyperFrames 用 HTML、CSS、JavaScript 构建视频，所以我们可以像设计网页一样，先做整套视觉系统。

这里可以用 Claude 做网页原型，也可以用 Open Design、Stitch 这类工具生成设计稿。重点是输入要清楚：深色科技背景、蜂窝纹理、金色标题、蓝色强调、玻璃面板、右侧人物视频栏。

参考图也很重要。它不是让 Agent 随便抄，而是让 Agent 学会画面层次：主标题有多大，功能卡放哪里，人物视频多高，底部进度线怎么走。

设计稿出来以后，先检查版式。概念解释场景，左侧必须是强文字信息栏，有小标签、英文 kicker、超大中文标题、短副标题、功能卡片和底部进度线。

右侧人物视频栏要和左侧保持统一高度。视频必须居中、满框、带金色边框和轻微发光，不能顶部留黑边，也不能用静态图片冒充视频。

操作演示场景则不同。主体应该是屏幕录制，前景层占最大面积；右下角可以放圆形移动 PIP，但它只是辅助讲解，不能抢走画面主体。

这就是 scene type 规则。概念讲解用左右分栏；屏幕操作用大屏录制加圆形 PIP；步骤过渡用深色步骤卡；结果展示用真实结果蒙太奇；总结收尾再回到人物或总结卡。

不能因为某一段出现圆形视频，就把所有人物都做成圆形。也不能因为某一段是教程，就把所有画面都塞进屏幕录制。先判断场景目的，再套组件。

第三步，把设计资产写成 Design.md。它不是一句“做高级一点”，而是给 AI Agent 的设计说明书。

它要明确字体体系、字号层级、主色和辅助色、背景纹理、卡片圆角、边框发光、视频裁切、字幕位置，以及每种场景的固定版式。

有了 Design.md，Agent 才不会每一段都重新发挥。它会在同一个视觉系统里扩展，避免后半段突然变成另一套风格。

第四步，准备带时间轴的脚本。口播视频的脚本不能只是普通文案，最好知道每一句话出现在第几秒，服务于哪个画面。

这也是为什么要声音先行。先生成完整主音轨，再做 ASR 字幕、DUIX 口型和 HyperFrames 画面。

如果顺序反了，就会出现有数字人时有声音，没数字人时声音断掉；或者字幕来自旧时间轴，嘴型来自别的片段，三者完全对不上。

主音轨生成后，用 ASR 得到字幕时间轴。字幕必须来自最终声音。只要 TTS 速度变了，就重新 ASR，不手动硬挪。

DUIX 也从同一条主音轨切片。比如一百九十秒到一百九十八秒出现人物，就切这一段音频，转成四十四点一千赫兹单声道 WAV，再提交给 DUIX。

这样，声音、字幕、嘴型都是同一个源头。最后 HyperFrames 只渲染静音画面，再把连续主音轨合成进去。

第五步，生成 storyboard.md。它是给 HyperFrames 的分镜说明书，要写清楚每个镜头的时间、用途、组件、文字、素材槽、入场和离场动效。

比如开头的 87 万统计，不只是放一个数字。左侧数据要进场放大，中间视频要 punch in，右侧框线要延伸出来，这些都要写成规则。

再比如左右分栏，不是随便一左一右。左侧必须是强文字信息栏，右侧是移动人物视频栏，两个区域的高度和视觉重量要统一。

屏幕演示则要保持一层背景、一层主体、一层必要 HUD。不要叠很多空框，也不要放没有内容的圆圈。画面越复杂，越要守住主体。

等设计、脚本、时间轴都准备好以后，Agent 就可以生成 storyboard.md。这个文件会包含视频规格、设计摘要、分镜节奏、画面目标，以及每个镜头要呈现的内容。

你可以把它理解成 HyperFrames 的施工图。没有施工图，Agent 只能临场发挥；有了它，Agent 才能按同一套模板稳定复刻。

所以完整流程是：先确定主题和脚本，再生成连续主音轨；再 ASR 出字幕；再从主音轨切 DUIX 驱动音频；再生成数字人口型视频。

接着准备屏幕录制和设计资产，把每个片段分类为统计开场、标题卡、概念分栏、屏幕演示、步骤卡、证明蒙太奇或总结收尾。

最后，用 HyperFrames 渲染无声画面，再把连续主音轨合成进去。这样声音不会断，字幕不会飘，数字人口型也不会因为场景切换而错位。

你在这期内容里看到的 HyperFrames 素材，基本都可以用这套流程制作。先准备设计资产，再准备带时间轴的口播脚本，然后生成 storyboard.md，最后让 Agent 根据分镜写 HyperFrames 代码并渲染成视频。

这套方法看起来步骤多，但它解决的是稳定性。一次跑通不难，难的是换主题、换数字人、换脚本以后，还能做出同样的版式、同样的节奏和同样的口播质感。

如果你自己尝试，建议先从二十秒模板开始。把声音、字幕、口型、画面全部对齐，再扩到两分钟，最后再做六分钟。不要一上来就追求全片，否则任何一个环节错了，后面都会一起错。
