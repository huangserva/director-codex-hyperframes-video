一、生产流程

Storyboard

先完成 storyboard.md：完整台词、分镜节奏、场景类型、素材槽、字幕和 DUIX 规则。

完整台词

从 storyboard 导出全片脚本；不要绕过 storyboard 直接改 HTML。

连续主音频

最终全片只用一条 master audio：accepted120 原声 + tail TTS。

FunASR 字幕

字幕时间轴必须来自最终 master audio 的 FunASR，并烧录成可见 caption clips。

DUIX 切片

从同一条 master audio 切出 dub.wav，驱动 DUIX 口型。

场景分类

按旁白目的标注 scene_type，再映射到固定组件。

真实视频资产

所有视频槽必须是真视频；DUIX 输出统一 gop30 重编码后再进入 HyperFrames。

HyperFrames 渲染

从 scene map 生成 index.html，视频层全部静音。

最终混音

渲染后用 ffmpeg mux 连续主音频。

视觉审查

抽帧检查版式、PIP 场景、字幕、视频运动、重复人物和空 HUD。

Final Gate

validate:final 必须通过，否则不能称为最终版。

八、核心规则速查

声音先行

没有完整 master audio、FunASR 字幕、caption timeline、DUIX slice map，不允许称为最终版。

字幕烧录

caption JSON 不等于成片字幕；final HTML 必须包含可见 .caption-line clips。

DUIX 静音

DUIX 视频只做口型画面；最终声音来自一条连续主音轨。

场景分类

先定 scene_type，再映射组件；不能凭视觉方便乱选版式。

圆形 PIP

只允许用于 screen_demo_pip，屏幕录制是主体，PIP 是辅助讲解。

概念分栏

concept_split 必须使用左信息栏 + 右视频栏，不能用圆形 PIP 替代。

禁止空 HUD

空圆环、无意义装饰框、四角取景线、旧 scaffold 都不能进入最终片。

Screen Proxy

screen_demo 主画面若来自原片，必须裁掉原片人物 PIP，再叠加新的 DUIX PIP，避免双人物。

gop30 资产

DUIX 输出和 proof 视频进入 HyperFrames 前统一重编码为 gop30，降低 seek/keyframe 风险。

视频必须动

概念上是视频的槽必须是真 mp4，并用相隔 0.5s 的帧检查确认不冻结。

DUIX 完成判据

success:true 不算完成；必须 data.status == 2 && progress == 100。

Final Gate

npm run validate:final 不通过，就不能交付为最终版本。
